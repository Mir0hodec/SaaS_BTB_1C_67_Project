# ИИ-помощник ГК «Эксперт»: инструкция администратора

Для того, кто ведёт помощника: добавляет сотрудников, подключает их базы, следит, чтобы бот работал. Почти всё делается в **панели управления**, командная строка не нужна.

## Как всё устроено

- Помощник работает на сервере компании, папка `C:\Claude CLI`. Это **системная задача Windows «Claude CLI bot»**: запускается вместе с сервером, перезапускается при сбое и не зависит от того, кто вошёл на сервер.
- Сотрудники пишут личные сообщения учётной записи **«Александр»** в 1С-Коннекте. Бот по очереди читает переписку с каждым сотрудником из списка и отвечает от имени «Александр».
- Отвечает **Claude Code по подписке** (без API-ключа). Под каким аккаунтом Claude работает бот — видно в панели.
- Базы 1С — **копии клиентских баз на компьютерах сотрудников**. Бот подключается к ним через обработку MCP Toolkit, которую сотрудник открывает в своей базе.
- Обработки и отчёты (.epf/.erf) бот собирает на сервере платформой 1С и присылает файлом.
- Старый бот в `C:\connect-bot` работает отдельно и параллельно. **Его не трогать**: не останавливать, не править.

## Где что находится

| Что | Где |
|---|---|
| Панель управления | `http://127.0.0.1:8010/panel` — открывается только на самом сервере, в Edge или Chrome (в Internet Explorer не работает), под любым пользователем Windows. Ярлык «Панель ИИ-помощника» на рабочем столе, адрес — в файле `C:\Панель ИИ-помощника.txt` |
| Ярлыки на рабочем столе (у всех пользователей) | «Панель ИИ-помощника», «Запустить ИИ-помощника» (запуск или перезапуск, если панель не открывается), «Сменить аккаунт Claude» |
| Расширение для сотрудников | папка `C:\Claude CLI\extensions` |
| Логи | `C:\Claude CLI\logs` — `bridge.log` (работа бота), `start.log` (запуск). Удобнее смотреть в панели, раздел «Логи» |
| Настройки | `C:\Claude CLI\config\settings.yaml`, сотрудники — `users.yaml`, базы — `bases.yaml`. Править лучше через панель |
| Токены баз и вход в Claude | `C:\Claude CLI\.secrets` и `C:\Claude CLI\.claude-bot` — доступ только у системы и администраторов. Не копировать и никому не отправлять |

## Панель управления

| Раздел | Зачем |
|---|---|
| **Обзор** | работает ли бот, аккаунт Claude, вопросы за 14 дней, последние ответы, очередь |
| **Сотрудники** | кому бот отвечает; добавить и убрать сотрудника |
| **Базы 1С** | базы сотрудников с MCP Toolkit: добавить, проверить, удалить; комплект файлов для сотрудника |
| **Журнал** | все вопросы и ответы, ошибки, время и стоимость ответа |
| **Проверки** | проверить Claude, API 1С-Коннекта, проверку контрагента, сборку обработки, базу знаний |
| **Настройки** | модель Claude, глубина рассуждений, как часто читать переписку, текст «Принял…»; версия, обновление, перезапуск |
| **Логи** | журнал работы бота в реальном времени |
| **Справка** | эта инструкция и инструкция для сотрудников (её можно скачать и распечатать) |

Кнопка **«Остановить»** вверху справа ставит бота на паузу: сотрудники получают «Помощник временно выключен», панель продолжает работать. Включить — той же кнопкой («Запустить»).

## Линия «ИИ-помощник»

Внутренняя линия поддержки только для сотрудников компании, клиенты её не видят. Сообщения из неё 1С-Коннект присылает боту сразу (вебхук), поэтому на линии бот отвечает без задержки и не тратит лимит истории переписки — сколько бы сотрудников ни писали.

- Создана скриптом `scripts\connect_line_setup.py`: линия, компетенция учётки «Александр», подключение сотрудников из списка бота, `connect.line_id` в настройках. Повторный запуск ничего не дублирует.
- В кабинете администратора 1С-Коннекта у линии включён **«Чат-бот → Внешний сервер для обработки данных»**: без этой галочки 1С-Коннект не отдаёт события боту.
- Адрес для вебхука бот получает сам — HTTPS-туннель Cloudflare (`tools\cloudflared.exe`), без домена и открытых портов. При перезапуске адрес меняется, бот сам переподписывается. Если что-то не так, смотрите «Логи → Запуск»: строки «туннель…» и «вебхук 1С-Коннект → …».
- На каждое сообщение линии бот обязан ответить в течение 30 секунд, иначе 1С-Коннект передаст обращение специалисту. Поэтому бот сразу пишет «Принял, работаю над ответом…», а сам ответ приходит следом.
- Проверить состояние: `.venv\Scripts\python scripts\connect_line_setup.py status` — по каждой линии видно, включён ли бот и куда идёт вебхук. Линия старого бота («Bilgir») не трогается.
- Линию видят все сотрудники и могут подключить её сами (подтверждается автоматически). Новым сотрудникам она подключается сама.

## Сотрудники

### Добавить

1. **Сотрудники** → справа найдите человека по фамилии → **«Добавить»**.
2. Скажите сотруднику писать «Александр» личным сообщением. Сообщения, отправленные **до** добавления, бот пропускает — пусть напишет заново.
3. Отправьте сотруднику инструкцию: **Справка → Сотрудникам → «Скачать файл»**, или пусть напишет боту `/инструкция`.

Если у сотрудника написано «нужно открыть доступ к переписке», учётке API 1С-Коннекта не хватает прав читать его чаты. Откройте доступ в администрировании 1С-Коннекта, иначе бот этого сотрудника не услышит.

### Сколько сотрудников можно добавить

1С-Коннект даёт **100 запросов истории в час на всех**, и старый бот расходует тот же лимит. Бот читает чаты по очереди: чем больше сотрудников, тем дольше ждать ответа. Примерное ожидание показано над списком. Если в логах появляется `OUT_OF_LIMIT`, увеличьте интервал в **Настройках** или уберите неактивных сотрудников.

### Убрать

Крестик в строке сотрудника. Переписка остаётся в журнале.

## Базы 1С сотрудников

### Как подключить базу

1. Сотрудник выполняет свою часть по «Инструкции для сотрудников»: пароль 1 у «Администратор», скрипт `employee_toolkit.ps1`, токен в MCP Toolkit. Вам он передаёт **адрес** (`http://<IP его компьютера>:6003/mcp`) и **токен**.
2. **Базы 1С → «Добавить базу»** и заполните поля:

| Поле | Что вписать |
|---|---|
| Название | понятное имя: «ГКЭ у Ивана Бубнова» |
| Код базы | латиница, цифры и `_`: `gke_ivan`. Потом не меняется |
| Хэштеги | по ним сотрудник выбирает базу: `гке, гкеиван` |
| Адрес MCP Toolkit | адрес от сотрудника |
| Токен MCP Toolkit | токен от сотрудника. Хранится в защищённой папке и обратно не показывается |
| Разрешить боту изменять данные | включите, если бот должен исправлять данные. Сотрудник при этом ставит в MCP Toolkit галочку «Записать» (блок «Автоматически разрешать операции») |
| Кто может работать с базой | обычно — только тот сотрудник, чья это копия. Пусто — все |

3. **«Сохранить»** → **«Проверить»**. Бот подключится к базе и проверит вход под «Администратор» с паролем 1.

| Результат проверки | Что значит |
|---|---|
| «Подключено: конфигурация, версия, пользователь Администратор» | всё готово, база доступна по хэштегу |
| «База недоступна» | у сотрудника не открыта база или MCP Toolkit, сменился IP или брандмауэр не пропускает |
| «Пароль «1» не подходит» | в копии базы у Администратора другой пароль — сотрудник должен поставить 1 |
| «База открыта под пользователем …» | сотрудник открыл базу не ярлыком «1С + MCP Toolkit» |
| «Токен не подошёл» | сотрудник сгенерировал новый токен — внесите новый (кнопка карандаша, поле «Токен») |

Если у сотрудника сменился IP-адрес, исправьте адрес базы тем же карандашом.

> Бот входит в базы **только** под «Администратор» с паролем «1». Это защита: если сотрудник случайно оставит в копии рабочий пароль, бот откажется работать и попросит поставить 1.

### Опубликованная база (расширение MCP_HTTPService)

Второй вид баз — база, опубликованная на веб-сервере, с установленным расширением **MCP_HTTPService**. ПК сотрудника и MCP Toolkit не нужны, но бот только **читает**: состав конфигурации, реквизиты объектов, данные запросами, журнал регистрации, формы. Исправлять данные в такой базе он не может — подскажет, что поправить, или сделает внешнюю обработку.

1. **Расширение в базу.** Файл `MCP_HTTPService.cfe` (лежит в `C:\Claude CLI\extensions`, бот присылает его по `/расширение`). В базе: Все функции → Стандартные → Управление расширениями конфигурации → «Добавить из файла». Снимите «Безопасный режим», перезапустите 1С.
2. **Публикация HTTP-сервисов расширений.** Конфигуратор → Администрирование → Публикация на веб-сервере → включите «Публиковать HTTP сервисы расширений по умолчанию» → «Опубликовать». Вручную — в `default.vrd` публикации: `<httpServices publishByDefault="true" publishExtensionsByDefault="true"/>`.
3. **Пароль.** У пользователя «Администратор» в этой базе — пароль **1**: бот входит только так.
4. **Проверка в браузере.** Откройте `http://сервер/ИмяБазы/hs/mcp-1c/version`, войдите как Администратор / 1 — должно показать `{"version": "0.4.8"}`.
5. **Подключение.** Обычно ничего делать не нужно: сотрудник присылает боту ссылку на базу, бот сам проверяет расширение и вносит базу в список — она появится в **Базах 1С** с хэштегом по имени публикации. Вручную: Базы 1С → «Добавить базу» → «Опубликованная база (расширение)» → адрес публикации (`http://сервер/ИмяБазы`, без `/hs/...`), название, хэштеги → «Сохранить» → «Проверить». Лишнюю базу из списка можно удалить крестиком — сама база не меняется.

| Результат проверки | Что значит |
|---|---|
| «Подключено: конфигурация, версия · расширение 0.4.8» | всё готово |
| «Не отвечает HTTP-сервис расширения MCP_HTTPService» | расширение не установлено в базу или HTTP-сервисы расширений не опубликованы (шаги 1–2) |
| «Пароль «1» не подходит» | у Администратора в этой базе другой пароль |
| «Нет связи с базой» | неверный адрес или сервер недоступен |

> Адрес публикации обычно `http://`: пароль уходит по сети открытым текстом. Поэтому так подключаются только базы, где у Администратора пароль 1, и никогда — с рабочими паролями.

### Комплект для сотрудника и расширение

Внизу страницы **Базы 1С** показан комплект, который бот присылает по команде `/toolkit`: MCP Toolkit для 64- и 32-разрядной 1С, скрипт настройки ПК, инструкция и расширение, если оно есть.

Чтобы раздавать **расширение конфигурации**, положите файл `.cfe` в папку `C:\Claude CLI\extensions`. Перезапуск не нужен: бот начнёт присылать его вместе с `/toolkit` и по команде `/расширение`. Чтобы заменить расширение — замените файл, чтобы перестать раздавать — удалите.

## Аккаунт Claude и лимиты

- Аккаунт, под которым отвечает бот, виден на **Обзоре**. Ссылка «сменить» показывает порядок смены:
  1. На рабочем столе сервера откройте ярлык **«Сменить аккаунт Claude»** и подтвердите запуск.
  2. В окне Claude введите `/login`, выберите вход по подписке (Claude account with subscription).
  3. Откройте ссылку из окна в **Edge**, войдите в нужный аккаунт Claude и нажмите **Authorize**.
  4. Скопируйте код со страницы, вставьте в окно Claude правой кнопкой мыши и нажмите Enter. Закройте окно.
  5. **Проверки → Claude Code → «Проверить»**: должен показаться новый аккаунт.
- Вход хранится в папке бота, а не в профиле Windows: от того, кто вошёл на сервер, он не зависит.
- Когда лимит подписки исчерпан, бот отвечает «Лимит подписки исчерпан. Обновится в ЧЧ:ММ» и до этого времени не тратит попытки. Расход видно в **Журнале** и на **Обзоре**.
- Чтобы экономить лимит: **Настройки** → модель Sonnet или Haiku, глубина «средняя».

## Обновление и перезапуск

- **Настройки → «Обновить с GitHub»** — скачивает новую версию, при необходимости ставит библиотеки и перезапускает бота. Через полминуты панель вернётся сама.
- **Настройки → «Перезапустить бота»** — если бот завис. Ответ, который бот сейчас пишет, оборвётся.
- Если панель не открывается — ярлык **«Запустить ИИ-помощника»** на рабочем столе.

## Проверки

| Проверка | Что проверяет |
|---|---|
| Claude Code | вход в подписку, версия, что боту доступны только нужные инструменты. Тратит один маленький запрос |
| API 1С-Коннекта | логин и пароль API, заново загружает справочник сотрудников |
| Проверка контрагента | сервис проверки контрагента по БИН/ИИН |
| Сборка обработки | собирает пустую обработку на сервере: установлены ли скиллы 1С, платформа и лицензия |
| База знаний | полная переиндексация папки «База знаний». Обычно бот делает это сам, когда файлы меняются |

## Проверить бота целиком на тестовой базе

Можно проверить всё — подключение базы, ответы, исправление данных, сборку обработки — без сотрудника. Скрипт создаёт на сервере маленькую тестовую базу с готовой ошибкой: третье поступление товаров не проводится, потому что у «Сахар» нет цены.

1. Откройте PowerShell от имени администратора и выполните:
```
cd "C:\Claude CLI"
.venv\Scripts\python scripts\test_base.py create
.venv\Scripts\python scripts\test_base.py open
```
2. Откроется 1С с окном MCP Toolkit. Прокрутите его вниз и в блоке **«Автоматически разрешать операции»** поставьте галочку **«Записать»**.
3. **Базы 1С → «Тестовая база помощника» → «Проверить»**: должно быть «Подключено … Тест помощника».
4. Спросите бота. Из 1С-Коннекта, если вы в списке сотрудников: «#тест почему не проводится третье поступление?», «#тест исправь цену сахара на 380 и проведи его», «#тест сделай обработку со списком номенклатуры без цены». Или прямо из PowerShell, без 1С-Коннекта:
```
.venv\Scripts\python -m bridge.cli "#тест почему не проводится третье поступление?"
```
5. Закройте 1С и уберите тестовую базу: `.venv\Scripts\python scripts\test_base.py remove`.

## Если что-то не работает

| Проблема | Что сделать |
|---|---|
| Бот никому не отвечает | **Обзор**: работает ли бот, не на паузе ли. **Проверки** → Claude Code и API 1С-Коннекта. **Логи** — последние ошибки |
| Панель не открывается | ярлык «Запустить ИИ-помощника»; подождите минуту и откройте панель снова |
| Не отвечает одному сотруднику | есть ли он в **Сотрудниках**, нет ли у него «нужно открыть доступ к переписке»; писал ли он после добавления |
| «Лимит подписки исчерпан» | дождаться указанного времени или сменить аккаунт Claude |
| В логах `OUT_OF_LIMIT` | лимит запросов истории 1С-Коннекта: увеличьте интервал в **Настройках** или уберите неактивных сотрудников |
| Сотруднику пишет «База недоступна» | база закрыта, сменился IP или мешает брандмауэр. Нажмите «Проверить» в **Базах 1С** |
| Бот не присылает обработки | **Проверки → Сборка обработки**. При ошибке выполните `scripts\install_1c_skills.ps1` |
| После обновления бот не запустился | **Логи → Запуск**; ярлык «Запустить ИИ-помощника» |

## Правила безопасности

- Старый бот (`C:\connect-bot`) не останавливать и не править.
- Пароли и токены не вписывать в файлы настроек и не пересылать в общих чатах. Токены баз вводятся только в панели.
- Пароль «1» — только для копий баз на компьютерах сотрудников, никогда в рабочих базах клиентов.
- Панель доступна только на самом сервере. Не открывайте к ней доступ из сети.
- Папки `.secrets`, `.claude-bot` и файл `.env` не копировать и никому не отправлять.
- Новые версии ставить только кнопкой «Обновить с GitHub».
