# ИИ-помощник ГК «Эксперт» в 1С-Коннект

Как бот из презентации «Claude в Телеграме», только канал — 1С-Коннект.
Сотрудник пишет во внутреннюю линию **«ИИ-помощник»** обычным языком и получает
ответ в тот же чат — из живой базы 1С или из базы знаний компании.

```
Сотрудник → линия «ИИ-помощник» → вебхук 1С-Коннекта → туннель Cloudflare → /connect/hook → очередь
         → Claude Code (Opus 5, high) → MCP → база 1С / база знаний
         ← ответ и файлы: REST SendMessageLine / SendFileLine от имени учётки бота
```

## Линия «ИИ-помощник»: как устроено

- **Линия своя и внутренняя** (`ServiceUsersAudience=FORSPECIALISTS`): клиенты её не видят, сотрудникам она доступна сразу. Создаёт её `scripts/connect_line_setup.py` (линия, компетенция учётке бота, `connect.line_id` в `settings.yaml`); в кабинете администратора 1С-Коннекта в карточке линии один раз включается «Чат-бот → Внешний сервер для обработки данных».
- **Приём** — вебхук: `SetHook type=line` на адрес туннеля Cloudflare (`tools\cloudflared.exe`, домен не нужен). Туннель и подписку поднимает и держит `scripts/start.py`; адрес туннеля меняется при перезапуске — подписка обновляется сама, состояние видно в панели.
- **Ответ** — REST `SendMessageLine` / `SendFileLine` с `bot_as_spec`: от имени учётки бота. На каждое сообщение бот сразу отвечает «Принял, работаю над ответом…» — у линии с внешним сервером на ответ 30 секунд, иначе обращение уходит специалисту.
- **Защита:** вебхук закрыт Bearer-токеном (сравнение в постоянном времени), дубли отсекаются по `message_id`, сообщения специалистов и самого бота игнорируются. У каждого сотрудника своя сессия — истории не смешиваются.
- Линия старого бота (`CONNECT_LINE_ID`) не используется никогда: на неё новый бот не подписывается.

Проверка доступа к API — `scripts/connect_check.py auth`, состояние линий и вебхука — `scripts/connect_line_setup.py status`.

## Панель управления

На сервере: **http://127.0.0.1:8010/panel** (порт — `port` в `config/settings.yaml`). Открывается только на самом сервере.

- **Обзор** — работает ли бот, подключена ли линия, на чей вопрос отвечает сейчас, аккаунт Claude, базы 1С, вопросы и расход за день и неделю, график за 14 дней.
- **Журнал** — все вопросы и ответы бота с фильтрами и поиском.
- **Базы 1С** — копии баз на ПК сотрудников (MCP Toolkit) и опубликованные базы (расширение): добавить, проверить, удалить.
- **Проверки** — Claude Code, API 1С-Коннекта, проверка контрагента, сборка обработки, переиндексация базы знаний.
- **Настройки** — модель, глубина рассуждений, сообщение «принял вопрос»; обновление с GitHub и перезапуск.
- **Логи** и **Справка** — журнал работы бота и обе инструкции.

Кнопки «Остановить» / «Запустить» в шапке: остановленный бот не отвечает (сотрудники получают «временно выключен»), панель продолжает работать.

### Бот как системная задача

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_service.ps1   # от имени администратора, один раз
```

Бот работает задачей Windows «Claude CLI bot» от имени системы: стартует вместе с сервером, не зависит от того, кто вошёл, поднимается сам после сбоя. Вход в Claude лежит в `.claude-bot` (доступ — только система и администраторы), Claude Code — в `tools\claude.exe`. На общем рабочем столе появляются ярлыки «Панель ИИ-помощника», «Запустить ИИ-помощника» и «Сменить аккаунт Claude», адрес панели — в `C:\Панель ИИ-помощника.txt`.

 Настройки пишутся в `settings.yaml` одной строкой, комментарии в файле сохраняются.

## Что умеет

| | |
|---|---|
| Вопросы по данным | `http://сервер/База почему не проводится поступление №15?` — база выбирается ссылкой на неё; новую опубликованную базу с расширением бот подключает сам |
| Помнит разговор | `а теперь по месяцам в Excel` — без ссылки, та же база; через час простоя — заново |
| Большие выгрузки | модель пишет запрос, мост проверяет его в 1С без выполнения, гонит по месяцам и собирает xlsx (фильтры, шапка, настоящие даты и числа) |
| Word и Excel | ответ на письмо, справка, сводная — готовым файлом в чат |
| Фото, PDF, файлы | скриншот ошибки — модель видит картинку; PDF/docx/xlsx читаются вместе с вопросом |
| Поиск по коду 1С | «где это считается», «какая процедура заполняет…» — по индексу выгрузки конфигурации, ответ со ссылкой `путь:строки` ([onec_rag/README.md](onec_rag/README.md)) |
| База знаний | документы из папки «База знаний», поиск с учётом словоформ |
| Команды | всем: `/базы` (свои базы и ссылки на них), `/новый`, `/помощь`, `/инструкция`, `/toolkit`, `/расширение`; владелец: `/пауза`, `/старт` |
| API-мост | `POST /api/ask` — тот же помощник для Langflow и внутренних сервисов (база — полем `base` или ссылкой в вопросе) |
| Журнал | `python scripts/stats.py` — вопросы, % без ошибок, время, цена, базы |

## Безопасность (базы боевые — агент только читает)

- **Кто может писать:** все сотрудники, подключённые к линии (`allow_all` в `config/users.yaml`); можно ограничить списком UUID — тогда остальным бот молча не отвечает.
- **Только нужные инструменты.** Терминал, файлы и сеть у агента отключены: `--permission-mode dontAsk` + `--disallowedTools`. Мост ещё и сверяет фактический список инструментов в событии `init`; если там лишнее, процесс убивается до первого хода модели.
- **Одна база на вопрос:** MCP-сервер 1С получает только выбранную базу.
- **Агент не видит секретов:** логин и пароль API Коннекта и токены — только у моста, из окружения агента они вырезаются. Агент стартует в пустой папке.
- **Текст из чата — не команда:** вопрос идёт через stdin как данные, в командной строке только фиксированные значения; ответ чистится от путей, имён инструментов и Markdown.
- **Приёмник:** Bearer-токен (сравнение в постоянном времени), дедупликация по `message_id`, эхо сообщений бота игнорируется.

## Запуск на сервере

Один раз, под тем пользователем Windows, под которым выполнен вход в Claude Code:

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```

Скрипт ставит зависимости и cloudflared, создаёт конфиги и `.env`, собирает базу знаний, проверяет Claude (`scripts/check_claude.py`), включает автозапуск при старте сервера (без окна консоли) и запускает бота. Какие доступы вписать в `.env` — в файле «Доступы ИИ-помощника.docx». В настройках API кабинета администратора 1С-Коннекта нужно разрешить API. Затем — `python scripts/connect_line_setup.py` и галочка «Внешний сервер для обработки данных» в карточке линии.

Дальше всё само (`scripts/start.py`):
- HTTPS-туннель Cloudflare и подписка линии на вебхук; пока 1С-Коннект её не принял — повтор раз в 5 минут;
- упал мост или туннель — поднимается заново;
- база знаний переиндексируется сама, когда меняется папка «База знаний».

Доступ: бот отвечает всем, кто пишет в линию (`allow_all: true` в `config/users.yaml`). Кто ставит бота на паузу, пишет боту `/id` и вписывает свой UUID с `owner: true`.

Логи: `logs/start.log`, `logs/bridge.log`. Статистика: `python scripts/stats.py`.

Проверка без Коннекта и подписки: `python -m bridge.cli` — консольный чат (`--base <код>` — сразу в базе; с `claude.binary: "scripts/mock_claude.cmd"` в `settings.yaml` — заглушка CLI).

## Отличия от Telegram-версии

- **Приём — вебхук линии** через туннель Cloudflare, а не long-polling. Входящих портов на сервере открывать не нужно.
- **«Печатает…» нет в API Коннекта** — вместо этого бот сразу отвечает «Принял, работаю над ответом…» (`connect.ack_text`).
- **Rich Messages нет** — ответ простым текстом, таблицы больше 20 строк уходят файлом.
- **Файлы** — в обе стороны: файл без подписи бот запоминает и ждёт вопрос к нему.

## Боевая база 1С

Базы описываются в `config/bases.yaml`, id — только латиницей. Для боевой базы нужен read-only HTTP-сервис и отдельная учётка только на чтение:

| Метод | Путь | |
|---|---|---|
| GET | `/hs/ai_readonly/metadata[?object=Документ.X]` | состав базы / реквизиты объекта |
| POST | `/hs/ai_readonly/query` `{"query","params","validate_only"}` | выборка; `validate_only` — проверка без выполнения |

Пока HTTP-сервиса нет, работает `mode: mock` на демо-данных.

## Базы 1С сотрудников (MCP Toolkit) и сборка обработок

- Копия клиентской базы на ПК сотрудника открывается под «Администратор» с паролем «1» и обработкой [MCP Toolkit](https://github.com/ROCTUP/1c-mcp-toolkit) во встроенном режиме (`http://<IP>:6003/mcp`, токен Bearer). Порядок для сотрудника — [docs/Инструкция для сотрудников.md](docs/), для администратора — [docs/Инструкция администратора.md](docs/) (обе открываются в панели, раздел «Справка»), скрипт `scripts/employee_toolkit.ps1`, файлы — команда боту `/toolkit`.
- База регистрируется в панели («Базы 1С»): адрес, владельцы, разрешение на запись; сотрудник выбирает её, прислав боту этот адрес; токен хранится в `.secrets/toolkit.json`, в процесс Claude попадает только переменной окружения.
- До запуска Claude мост проверяет: база открыта (`/health`), токен подходит, сеанс под «Администратор» и пароль «1» (по отпечатку пароля, сам пароль не нужен). Иначе — понятный отказ без траты лимита.
- Инструменты базы: `get_metadata`, `execute_query`, `get_event_log`, `find_references_to_object`… и `execute_code` при `write: true` (в MCP Toolkit — автоподтверждение «Записать»). Анонимизация MCP Toolkit поддерживается (`submit_for_deanonymization`).
- Внешние обработки и отчёты бот собирает на сервере MCP-сервером `dev` (скиллы [cc-1c-skills](https://github.com/Nikolay-Shirokov/cc-1c-skills), установка — `scripts/install_1c_skills.ps1`) и присылает `.epf/.erf` в чат. Терминала у бота нет: белый список скиллов, только своя рабочая папка, платформа и базы задаются сервером.

## Поиск по коду 1С

Память по коду конфигурации — модуль `onec_rag`: индекс выгрузки в одном файле SQLite (FTS5) и MCP-сервер `onec_code` с инструментами `search_1c`, `get_module`, `find_object`. Работает без выбора базы. Установка одной командой:

```powershell
powershell -ExecutionPolicy Bypass -File onec_rag\install.ps1 -RepoPath "D:\1c-dumps\base" -RepoName base
```

Смысловой поиск (векторы в том же файле, модель на CPU) — тот же скрипт с ключом `-Semantic`. Индекс обновляет Планировщик задач (`git pull` + доиндексация раз в 10 минут), постоянных процессов нет. Подробно — [onec_rag/README.md](onec_rag/README.md). Старый `search_code` (подстрока по `code_dump_dir` выбранной базы) оставлен как запасной.

## Проверка контрагента

`counterparty_check_client.py` — HTTP-сервис 1С `CounterpartyCheck` (POST, Basic Auth, `{"bin": ...}`).
Настройки только из окружения (`COUNTERPARTY_CHECK_URL`, `_LOGIN`, `_PASSWORD`, `_TIMEOUT_SECONDS`); для консоли можно положить их в `.env` (образец — `.env.example`, сам `.env` в `.gitignore`).

```bash
python counterparty_check_client.py 750710450345
```

`check_counterparty(bin, calculation_datetime=None)` возвращает `status`:
- `ok` — обычный сценарий;
- `needs_manager` — долг > 0 или есть неподписанные ЭАВР, передать клиент-менеджеру;
- `error` — проверить не удалось, это не «чистый» контрагент.

Код выхода консоли: 0 / 2 / 1 соответственно. Пароль и `Authorization` вычищаются из логов и текста ошибок.

В боте: если задан `COUNTERPARTY_CHECK_URL`, у агента появляется инструмент `check_counterparty` (сервер `mcp_counterparty`). Сотрудник пишет «проверь контрагента 750710450345» — бот называет долг, неподписанные ЭАВР и решение. Логин и пароль сервер берёт из окружения, которое наследует от `claude`, в MCP-конфиг на диске они не пишутся.
